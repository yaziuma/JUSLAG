# 手動執行戦略の再検証（2026-10-01）

## 結論

`pca_sub_long_5d_manual_v2`の固定5日・現物ロングは、実運用と同じ資金90%投入で再計算しても、取得済みデータの最終決済日2026-09-29まで利益優位が残っている。戦略上の見送りフィルタは設けていない。直近の連続停止は、最新米国終値が08:55 JSTまでに確定せず、対象JPX営業日を過ぎたレポートしか生成できなかった運用上のブロックである。

一方、古いシグナルを翌日へ繰り越す単純な回避策は不採用とする。1 JPX営業日の追加遅延で損失となり、最大ドローダウン停止条件も超えるためである。注文回数を増やすために期待値を捨ててはならない。

## 次の実装課題

連続停止を減らしつつ精度を維持するには、シグナル時刻を遅らせるのではなく、米国終値取得を08:55 JSTまでに完了させる必要がある。

同日、Yahoo bulk応答の最新行で終値が欠けた銘柄だけを、yfinanceの銘柄別history経路で再取得する処理を`src/juslag/data_loader.py`へ追加した。価格調整モードはbulkと一致させ、成功行は既存の観測履歴付きキャッシュへupsertする。個別経路が失敗してもbulk結果は破棄しない。実データ再取得では、従来9月29日で止まっていた米国11銘柄のraw終値を全て9月30日まで回収し、全銘柄の日付一致を確認した。全テストは324件成功した。

さらに、日次処理の一括取得後にバックテスト2本と日次シグナルが同じデータを再取得していた処理を廃止した。最初の`run_fetch_all()`だけが提供元へアクセスし、後続計算は同一キャッシュスナップショットを読む。`--skip-fetch`のE2Eで外部通信なしにレポート生成が完了し、全テスト325件が成功した。これにより提供元への要求回数、レート制限リスク、08:55までの処理遅延を減らす。

この対策は同一提供元内の要求経路冗長化であり、提供元全体の停止には耐えない。第二データ源は価格調整基準と利用条件を確認したうえで別途追加する。注文票は従来どおり11米国入力と17国内銘柄の全件終値、日付一致、freshness、異常値拒否を満たす場合だけ生成する。

全バックテストを含む日次レポートとは別に、発注に必要な価格とPCAシグナルだけを生成する`manual_strategy_signal_snapshot.py`を追加した。08:35、08:42、08:48 JSTに再試行し、08:50のpreflightは締切前の最新スナップショットを候補に含める。銘柄順位のシグナルはバックテストと同じadjusted価格、注文数量は実際の名目額と一致するraw価格を別々に取得する。通常日次・軽量の両経路は`manual_strategy.yaml`からPCA 60/3/0.9と上位20%を読み、スナップショットへ記録する。preflightはrawシグナル、旧形式、またはモデル条件が正本と違う候補を除外する。2026-10-01の実ホストE2Eは15.29秒、adjusted/rawとも17銘柄、鮮度OK、欠損0で完了した。入力JSONとraw数量算定CSVはそれぞれSHA-256を注文票へ記録する。

同日の保存済みliveスナップショットを、検証器と同じadjustedキャッシュ、2021-12-31までのpretrain、PCA 60/3/0.9から独立に再計算した。基準日2026-09-30の17銘柄すべてで最大絶対スコア差0.0、配列は完全一致し、上位4銘柄も`1617.T`、`1627.T`、`1620.T`、`1630.T`で一致した。これにより、少なくとも当該実データでは検証経路とlive生成物の数値的同一性を確認した。

利益は将来保証ではない。今回の結果は、現行戦略を維持する根拠と、単純な遅延発注を拒否する根拠である。
