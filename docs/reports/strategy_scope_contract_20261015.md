# 08:55期限とopen_gapの適用対象（2026-10-15）

## 結論

実運用として記載された手動固定5日戦略は、寄付前に既知の米国シグナルと前JPX営業日のraw終値を使う。当日open_gapを朝の必要条件にしない。08:55期限と09:00寄付が、この戦略で矛盾しているわけではない。

旧日次メタ戦略は研究比較として残され、当日open_gapを使う。この研究判定の `tradeable=false / strategy_rule_skip` と、手動戦略のpreflight READYは適用対象が異なる。

## 08:55が意味するもの

- `docs/reports/manual_strategy_establishment_20260922.md` の固定ルールは「対象JPX営業日の08:55 JSTまでにSBIで寄成」。これはプロジェクトの発注運用期限であり、取引所の寄付時刻や全銘柄についてのSBI受付保証時刻を表すものではない。SBI画面で受付不能・規制・余力不足等があればバッチ全体を見送ると同資料に記載されている。
- `config/manual_strategy.yaml` の `entry_order_deadline_jst` は08:55。`manual_strategy_preflight.py` はこの時刻をソース採用期限と現在時刻の拒否判定に使う。08:55後は `entry deadline has passed`。
- `manual_strategy.py::build_execution_intent` は同じ期限からexpires_atを作る。08:55以降に有効な新規窓を作らない。この調査では同関数を呼んでいない。
- 08:42は最終preflight・intent releaseの時刻であり、08:55期限そのものではない。`docs/reports/order_release_timing_fix_20261005.md` とcommit `e9213ad` は、承認時間を広げるため08:40 snapshot /08:42 releaseへ前倒しし、08:55は維持したと記録する。
- バックテストの紙上約定時刻を08:55とする定義ではない。評価上の約定は次JPX寄付、実際の価格は寄付後の記録であり、朝の数量算定は前JPX終値を使う。

## open_gapの段階別用途

| 段階 | 必要性と根拠 |
|---|---|
| 手動戦略の寄付前シグナル・数量算定 | 不要。`manual_strategy.py::build_order_sheet` は全17銘柄のraw signalから設定分位を選び、渡された既知raw価格で数量算定する。旧研究判定のtradeable、open_gap、positionの見送り結果を新規条件にはしていない |
| 手動preflight | 不要。対象JP日・adjustedシグナル・モデル条件・freshness・締切前の生成時刻を確認してソースを採用し、その後に保有/資金/DD等の既存条件を処理する |
| 旧日次メタ戦略の事前判定 | `rule_406_no_flip` はabs(open_gap)<=1.5%を要求し、欠損ならskip。寄付前の値は観測不能なので、同じ寄付で執行する判定としては使えない |
| 寄付後の研究評価 | 観測後のgapで再評価できるが、同値寄付を前提にした執行は `assumed_open_fill_expired` で拒否。寄付後エントリーへ自動変更しない |
| バックテスト | 旧メタ版は実際の当日寄値からgapを算出して条件を評価する。同値寄付の執行可能性が証明されたわけではない。手動5日版では当日寄値は建玉・損益・コストの評価に使い、事前の選別条件に使わない |

## 隔離修正

手動戦略の選別・資金・停止条件、08:55期限、旧メタ版のgapフィルタは変更しない。通知とreport/snapshotに運用・研究のスコープを明記する。研究用バックテストの旧「現行運用」見出しを「旧日次研究」へ変更する。手動preflightがない画面では、研究判定で発注準備完了を代用しない。新しいREADYや発注許可は生成しない。

寄付後診断timerは本番適用保留。寄付データ取得を08:55前へ成立させる解決策でも、手動戦略の必須条件でもない。

## 収集成功と証拠充足も区別する

元のintraday収集処理は、全17銘柄の有効バー取得を成功条件にしており、全銘柄の09:00:00完全一致を要求していない。未適用の初期修正案で加えた「時刻ずれがあれば収集自体を非ゼロ終了」は取り下げた。既存17銘柄条件は維持し、当日基準のカバレッジ判定を修正する。時刻ずれの証拠診断はBLOCKEDのまま別に出力し、寄付成立を断定しない。A2の90%カバレッジ・20分以内等の凍結条件も変更しない。

## 要件として残す確認

`config/a_evaluation_gate.yaml` の9/19 No-GoとA3凍結（上位30%・2027-03-23まで）は残っており、後発の手動v2（上位20%）採用資料とは評価対象・採否の扱いを同一視できない。現在の手動preflightはこのファイルを読まず、READMEと後発の採用資料は手動v2を実運用戦略として記載する。コードと履歴から現在の実装契約は確認できるが、9/19ゲートを全戦略へ適用する意図か、旧研究の凍結として扱う意図かの正式な承認関係までは証明できない。

既存のNo-Goをtrueへ変える、手動preflightへ新しい全体ゲートを追加する、旧メタ版を実運用へ戻す等は別の採否・リスク判断になるため実施しない。必要なら要件所有者が適用対象を明示して、日付付きの採否資料とテストを揃える。
